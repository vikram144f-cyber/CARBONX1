- (decision) AD-1 Paradigm: layered monolith. Next.js App Router owns all rendering and all API routes; a Service Layer owns all domain logic; Prisma owns all DB access. No unit calls another layer's internals. Binds: module coupling. Prevents: route handlers with embedded SQL or business logic.
- (decision) AD-2 Stack lock: Next.js 14+ App Router, TypeScript strict, Tailwind CSS, PostgreSQL, Prisma, Turf.js (server-only), viem, NextAuth.js (database sessions), TanStack Query + RSC, Vercel + Neon. No alternatives without an AD. Binds: technology choices. Prevents: stack fragmentation.
- (decision) AD-3 All API keys and secrets live in server-side environment variables only. No secret may appear in source code, a NEXT_PUBLIC_ variable, or a client bundle. All external service calls originate exclusively from lib/services/**. Binds: secret handling. Prevents: credential exposure.
- (decision) AD-4 Single source of truth: PostgreSQL is the operational system of record. Blockchain is a tamper-evident evidence-anchoring layer only — it stores no application state. The relational DB drives all UI state. Binds: state ownership. Prevents: blockchain-as-DB misuse.
- (decision) AD-5 Risk Engine separation: Turf.js geospatial calculations and the RiskEngine scoring function are deterministic, versioned, server-side, and the sole source of numeric outputs. The AI layer receives only structured JSON from the RiskEngine and may not compute, invent, or override those values. Binds: calculation authority. Prevents: AI hallucinating numbers.
- (decision) AD-6 Evidence labelling contract: every EvidenceRecord carries one of OBSERVED | ESTIMATED | MODELED | INFERRED. A point-buffered zone is always ESTIMATED. No output may omit or downgrade this label. Binds: evidence integrity. Prevents: presenting estimates as confirmed damage.
- (decision) AD-7 Incident state machine enforcement: all status transitions go through AuditService.transition(). Disallowed transitions throw InvalidTransitionError. No route handler or UI component may write IncidentStatus directly. CARBONX never writes a status of CREDIT_INVALIDATED. Binds: state integrity. Prevents: illegal status bypasses.
- (decision) AD-8 Assessment immutability: RiskAssessment records are append-only. A correction creates a new record with supersededById pointing to the old one. No record is silently overwritten. Each assessment stores engineVersion, methodologyVersion, boundaryId, inputEvidenceIds, and assumptions. Binds: reproducibility. Prevents: silent recalculation.
- (decision) AD-9 Blockchain failure isolation: a failed or pending blockchain anchor must never block or rollback the incident workflow. The operational workflow must complete with anchor status PENDING or FAILED. Retry is background, max 3 attempts, exponential backoff. Binds: resilience. Prevents: blockchain outage halting audit work.
- (decision) AD-10 AI failure isolation: an AIReport generation failure sets the report to null. The incident detail page shows Interpretation Unavailable. Deterministic assessment data and all audit actions remain fully available. Binds: resilience. Prevents: AI outage blocking human review.
- (decision) AD-11 3D independence: the R3F scene is a conditionally-rendered overlay, dynamically imported with ssr:false. It receives all data as props from the parent React page — it never calls APIs directly. A WebGL-unavailable device shows a 2D fallback. The complete P0 workflow must be achievable without mounting the 3D scene. Binds: 3D isolation. Prevents: 3D failure blocking business-critical operations.
- (decision) AD-12 Async work mechanism: AI generation and blockchain anchoring are non-blocking fire-and-forget calls from the ingestion service, executed with Promise.allSettled after the synchronous assessment is persisted. For production retry jobs, Next.js background tasks (waitUntil on Edge) or a lightweight queue via pg-boss (PostgreSQL-backed) is the only permitted mechanism. No setTimeout fake async. Binds: async work pattern. Prevents: route handler timeouts and fake background jobs.
- (decision) AD-13 GeoJSON coordinate mapping: event geometries and project boundaries are stored in WGS84. Turf.js receives raw GeoJSON — never pre-projected coordinates. The correct Turf.js v6 intersection call is turf.intersect(poly1, poly2), not a FeatureCollection form. 3D scene coordinates use a local flat projection derived at runtime from the project centroid. Binds: coordinate system contract. Prevents: incorrect intersection results.
- (decision) AD-14 Canonical hash determinism: the blockchain evidence package is serialized as JSON.stringify(obj, sortedKeys) where sortedKeys are the top-level keys sorted alphabetically, and nested values are pre-sorted arrays. The hash is keccak256 of the resulting UTF-8 string. The canonical schema version is anchor-v1.0. Binds: hash integrity. Prevents: non-deterministic hashes breaking verification.
- (decision) AD-15 Zod schema authority: all request/response contracts live in lib/validations/. Route handlers (server) and TanStack Query fetchers (client) import from this single location. No schema duplication. A schema change requires updating both sides atomically. Binds: API contract. Prevents: client-server type drift.
- (decision) AD-16 Developer ownership partitions: A=prisma/+lib/services/geospatial+risk+ingestion+audit+app/api; B=app/pages+components+features(non-3D)+lib/validations; C=lib/services/ai+blockchain+contracts; D=features/investigation-3d+public/models+textures. DB migrations created by A only, reviewed in PR. prisma generate runs after every schema change, generated client not committed. Binds: team boundaries. Prevents: migration conflicts and ownership ambiguity.
- (decision) AD-17 MONITORING status entry: a project is in MONITORING (no active incident) by default. EVENT_DETECTED is written only when an environmental event intersects the project boundary and an Incident record is created. MONITORING is a derived portfolio-level display state, not a persisted Incident status — incidents do not have a MONITORING row in IncidentStatusHistory. Binds: status semantics. Prevents: unreachable MONITORING state or phantom Incident records.
- (decision) AD-18 Priority alignment: the optional 3D investigation is P1. P0.5 (presentation-critical) includes polished 2D UI, Leaflet map with geofence/impact overlays, risk/confidence indicators, and the audit workflow. 3D scene work begins only after P0 pipeline is verified end-to-end. Binds: build order. Prevents: 3D blocking core pipeline delivery.
- (assumption) Turf.js v6 is the pinned version. API: turf.intersect(poly1, poly2). Verify on install — v7 may change signatures.
- (assumption) NASA FIRMS CSV/JSON API is freely accessible with a registered key. Rate limits acceptable for demo-scale ingestion.
- (assumption) Neon or Supabase free tier supports the Prisma connection-pooling mode required by Vercel serverless functions.
